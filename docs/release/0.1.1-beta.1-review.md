# codex-agent-tools 0.1.1-beta.1 发布审阅

日期：2026-07-30

状态：本地确定性门禁通过；等待 PR/CI、GitHub Actions OIDC beta 发布、公共 npm
隔离验收和修复版真实宿主复验。

## 发布目的

`0.1.1-beta.0` 已修复插件相对 runtime 缺少工作目录的问题。维护者彻底退出并
重新打开 Codex 后，新建任务首次从版本化插件缓存发现了
`external_review` / `external_delegate`，同时保留旧
`cc_review` / `cc_delegate`，证明 `cwd: "."` 修复有效。

真实 Kimi K3 宿主 review 随后通过；Ark Coding Plan 宿主 review 在启动 Pi 前
以“缺少凭据”失败。只读进程环境核对只报告变量是否存在，不读取或记录值，确认
父 App 进程拥有 `API_KEY_DOUBAO_CODING`，但插件 MCP 没有收到它。

根因是 stdio MCP 配置没有声明 `env_vars`。Codex 官方配置参考把
`env_vars` 定义为从本地父环境转发给 stdio MCP 的变量白名单；`env` 才是静态值。
插件原 manifest 两者都没有，因此活动宿主按隔离边界没有转发 Ark 凭据。

## 改动范围

- 插件 `.mcp.json` 增加精确 `env_vars` 白名单：
  `ARK_API_KEY`、`VOLCENGINE_API_KEY`、`API_KEY_DOUBAO_CODING`、
  `OPENAI_API_KEY_DOUBAO`；
- manifest 不含静态 `env`，不保存任何凭据值；
- artifact 测试、release smoke、隔离插件验收和公共 npm 消费者验收精确验证
  白名单及静态值禁令；
- 隔离验收和公共 npm 验收按 manifest 白名单构造 MCP 环境，不再把完整父环境
  直接传给测试 transport；
- package、lock、runtime 和插件 manifest 统一升级到 `0.1.1-beta.1`；
- 不改变逻辑 LLM 注册表、真实模型、provider/route、凭据优先级、工具 schema、
  子进程最小环境、结果 validator 或历史能力 evidence。

## 发布停止条件

若完整离线门禁、Node 20/22/24 CI、GitHub Actions 发布、公共 npm 隔离验收或
修复版真实宿主 Pi/delegate/取消清理任一失败，则保留 `0.1.0` 为 npm
`latest`，不得发布 stable，不得恢复开发期直连、手工修改活动配置、移除旧
`codex_cc_tools` 或修改 Claude Code。
