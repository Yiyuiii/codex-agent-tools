# codex-agent-tools 0.1.0-beta.0 发布审阅

日期：2026-07-29

状态：本地候选门禁、发布/OIDC 独立复审和 npm 隔离修复复审已通过，公开仓库

## 发布目的

`0.1.0-beta.0` 是 npm 包名首次注册用的 bootstrap prerelease。包存在后才能在
npm 配置 GitHub Actions Trusted Publisher；后续 `0.1.0-beta.1` 必须由
GitHub OIDC 发布，并从公共 registry 完成隔离消费者验收，稳定版不得直接复用
beta.0 的手工发布路径。

## 独立复审收敛

- 首个 31 文件对抗审阅包在 MCP 900 秒上限超时，没有结论，不计 PASS；
- 发布/OIDC 窄审返回 **PASS**，确认 tag、version、next/main ancestry、stable
  evidence、public registry/access、OIDC 权限、既有版本和 dist-tag 传播路径
  没有阻断缺陷。报告提出“release smoke 可能未调用 package identity”和“既有
  版本可能不校验 dist-tag”，代码复核分别由
  `scripts/release-smoke.mjs:137` 与 workflow 的 exact package/dist-tag 循环
  直接反证，因此未采纳；
- npm 隔离初审命中一个 **HIGH blocker**：`npm view/install` 未显式传 env/cwd，
  可能读取宿主 `.npmrc`、cache 或 token。现新增只保留系统执行变量的隔离环境，
  把 HOME、Codex home、AppData、TEMP/TMP/TMPDIR、npm userconfig/globalconfig/
  cache 全部指向一次性目录，三个 npm 调用都使用空 install cwd 与该环境；
- 同一初审建议用本包 CLI 替代裸 `codex`，该建议不成立：本包 CLI 只提供
  `doctor`，官方插件生命周期必须由宿主 `codex plugin` 驱动；其 HOME、
  `CODEX_HOME`、AppData 与凭据已隔离，缓存副本 MCP 又被单独启动并核对合同；
- 隔离修复定向复审返回 **PASS**，确认原 HIGH blocker 关闭且官方 Codex
  测试器边界正确。两个 LOW 项（Unix `TMPDIR`、npm cache 预创建）也已主动修正；
- 能力指纹本轮窄审返回非 JSON、无结论，不计新 PASS。该核心在能力级迁移阶段
  已有两轮 Ark 独立复审无 P0/P1；本轮仍由 160 项聚焦回归、8/8 verifier、
  release smoke 与 Node 20/22/24 CI 覆盖，历史 evidence/manifest 未改写。

最终候选提交 SHA、隔离修复 CI 和 bootstrap 发布结果将在执行后追加；任一缺失
时不得把本记录写成发布完成。

## 已知风险与停止条件

- 本机 npm 当前未认证；首包需要一次 npm web login。认证未完成时停止在发布前，
  不改用长期 token 写入仓库或 workflow。
- beta.0 只用于注册包和建立 Trusted Publisher；若公共安装或插件生命周期失败，
  使用新的 beta 序号修复，不复用已发布版本。
- package `publishConfig`、手工 bootstrap 命令和 OIDC workflow 三层均固定
  `https://registry.npmjs.org/` 与 public access；release assurance 会拒绝
  registry 或 access 漂移。
- Trusted Publisher 配置固定由 `npm@11.18.0` 执行，因为本机默认 npm 11.11.0
  使用不同的权限参数。`--dry-run` 已确认 `codex-agent-tools`、
  `Yiyuiii/codex-agent-tools`、`release.yml` 与 publish 权限解析正确；真实执行
  仍必须在首包存在后完成 2FA。
- GitHub tag 必须可从 `next` 到达；稳定 tag 必须可从 `main` 到达并包含
  `.release-validation/v0.1.0.md`。
