# Kimi External Agents MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可由 Codex 安装和调用的 `codex_external_agents` MCP 服务，并通过本机 Kimi Code 为三个逻辑 Kimi LLM 提供 `external_review` 与 `external_delegate`。

**Architecture:** TypeScript MCP 服务器只暴露两个稳定工具，由任务服务解析必填 `llm` 并查找版本化注册表。Kimi 适配器通过官方 ACP SDK 启动一次一进程的 `kimi acp`，环境、权限、取消、硬超时、并发和工作区证据都在桥接层实施；首个里程碑不引入 Pi，也不修改旧仓库或 Claude Code。

**Tech Stack:** Node.js 20+、TypeScript 7、ESM、`@modelcontextprotocol/sdk` 1.29、`@agentclientprotocol/sdk` 1.2、Zod 4、Commander 14、Vitest 4、tsup 8、原生 `node:child_process`/`node:fs`/`node:stream`。

---

import { KeyedLimiter } from "../../src/runtime/limiter.js";

describe("KeyedLimiter", () => {
  it("removes an aborted waiter without consuming a slot", async () => {
    const limiter = new KeyedLimiter(() => 1);

- [ ] **Step 3: 实现最小队列和经过真实测试的树终止器**

`KeyedLimiter.run(key, signal, work)` 为每个逻辑 LLM 维护 active/queue；等待者注册一次性 abort 监听器，出队或取消时移除监听器，`finally` 释放槽位并启动下一个等待者。

`terminateProcessTree` 在 Windows 调用系统 `taskkill.exe /PID <pid> /T /F`，并把退出码 128（目标已经结束）视为幂等成功；POSIX 对以 detached 方式启动的进程使用 `process.kill(-pid, "SIGTERM")`，短暂宽限后使用 `SIGKILL`。这是首版已验证后备路径；在没有可维护 Node Job Object 绑定的情况下，不加入未经验证的原生依赖。公共调用只依赖该抽象，后续可换成 `KILL_ON_JOB_CLOSE` 实现。

`client.ts` 使用官方 SDK 的以下连接骨架，并把模型设为注册表固定值：

```ts
const stream = acp.ndJsonStream(
  Writable.toWeb(child.stdin),
  Readable.toWeb(child.stdout)
);

const response = await acp.client({ name: "codex_external_agents" })
  .onRequest(acp.methods.client.session.requestPermission, handlePermission)
  .onRequest(acp.methods.client.fs.readTextFile, handleRead)
  .onRequest(acp.methods.client.fs.writeTextFile, handleWrite)
  .connectWith(stream, async (ctx) => {
    await ctx.request(acp.methods.agent.initialize, {
      protocolVersion: acp.PROTOCOL_VERSION,
      clientCapabilities: { fs: { readTextFile: true, writeTextFile: false } }
    });
    return ctx.buildSession(cwd).withSession(async (session) => {
      await ctx.request(acp.methods.agent.session.setConfigOption, {
        sessionId: session.sessionId,
        configId: "model",
        value: model
      });
      void session.prompt(prompt);
      for (;;) {
        const update = await session.nextUpdate();
        if (update.kind === "stop") return { response: update.response, sessionId: session.sessionId };
        collect(update.notification);
      }
    });
  });
```

从 `session.newSessionResponse.configOptions` 中选择 `category === "model"` 的 select 项，并在它的 options 中按 value/name 匹配注册表 model；随后向 `session/set_config_option` 发送 `{ sessionId, configId: option.id, value: selected.value }`。找不到模型选项就以明确诊断失败，不能静默使用默认模型。review 的反向 `readTextFile` 先 `resolve`/`realpath` 再用 `path.relative` 验证位于 cwd；写入总是返回拒绝，permission request 选择 agent 提供的 deny/cancel option。硬期限只看总 elapsed time，不把 stdout 沉默当超时；每 15 秒向 MCP 进度回调发送桥接心跳。
